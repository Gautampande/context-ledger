## Canary coverage

The canary used dedicated, non-sensitive, user-owned public ChatGPT shares. No share URLs, transcripts, snapshots, archive IDs, screenshots, or account data are published with this report.

| Scenario | Visible turns | Result |
| --- | ---: | --- |
| Short conversation with a code-fence boundary | 2 | Pass; the display transcript keeps the following turn heading outside an otherwise unterminated source fence. |
| Multi-turn plain-text conversation | 8 | Pass; all visible turns remained ordered and separate. |
| Rich formatting | 2 | Pass; visible heading, bullet text, Unicode, link text, table, and fenced JavaScript were preserved. |

For a pass, the generated `transcript.md` was compared manually to the visible shared conversation. A pass means no visible user/assistant turn was missing, duplicated, reordered, merged, or materially altered.

## Interpretation and limits

This is a small, maintainer-run live canary. It supports the narrow claim that the tested `chatgpt-share-react-router/0.3` surface worked for these three user-owned examples on the stated date.

It does **not** establish broad ChatGPT compatibility, account-export fidelity, provider provenance, completeness outside the fetched public page, or support for Claude/Gemini. The adapter continues to fail closed on unsupported visible representations. Twenty manually compared shares remain a rolling confidence target before any broad-support claim.
