# v1.3.0 offline ChatGPT snapshot replay

## Goal

Allow a supported public ChatGPT share page that was captured locally once to be imported later without revisiting the share URL. This makes a capture reproducible after a link expires or is revoked, while keeping the existing narrow parser and no-token default.

## Workflow

Capture the page once using the existing bounded fetch command:

```sh
node src/cli.js fetch-share --url 'https://chatgpt.com/share/...' --out snapshots
```

For a ChatGPT snapshot, replay that exact HTML and metadata pair locally:

```sh
node src/cli.js import-chatgpt-snapshot \
  --input snapshots/snapshot-<digest>.html \
  --metadata snapshots/snapshot-<digest>.json \
  --out archives
```

The replay import makes no network request. It verifies that the HTML byte count and SHA-256 match strict `shared-snapshot/0.1` metadata before the ChatGPT parser reads the HTML. The resulting archive uses `capture_method: "public_shared_snapshot"` and preserves the source URL digest, source HTML digest, parser version, and `visible_snapshot` limits.

## Security boundary

- Keep snapshots private. The HTML can contain the conversation text, and the source URL may be recoverable from other local artifacts even though Context Ledger does not write it into metadata or archives.
- A matched local HTML/metadata pair detects accidental or unauthenticated changes to that pair. It does **not** prove that the snapshot originated at ChatGPT, that it is complete, or that a local attacker did not replace both files consistently.
- Only metadata with `provider: "chatgpt"` is accepted. Claude and Gemini snapshots remain opaque acquisition outputs; they are not transcript inputs.
- The same visible-text-only parser and fail-closed rules apply. Unsupported visible artifacts still produce no archive.
- Snapshot files are never committed to Git. Use an ignored directory such as `snapshots/` or `work/`.

## Acceptance criteria

1. A snapshot generated by `fetch-share` can be imported after the original share is no longer fetched.
2. The import performs zero network requests and zero AI calls.
3. Tampered HTML, byte counts, digests, metadata shape, or a non-ChatGPT provider are rejected before archive creation.
4. The result verifies with `verify-index` and retains the same parser and visible-snapshot limitations as a live ChatGPT import.
5. Automated coverage includes success, archive validation, CLI output, and failed metadata/provider cases.
