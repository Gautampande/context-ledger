# v2.0.0 portable single-conversation package

## Purpose

`v2.0.0` adds the missing portable artifact from Context Ledger's original one-conversation workflow. A package is one local `.aicx` file that a person can copy to another machine or share through an appropriate private channel. It is not an upload to ChatGPT, Claude, Gemini, or any other provider.

The recipient imports the package locally, verifies it, generates a reviewed handoff, and then uses the destination chat product's ordinary paste or attachment interface. The tool never logs into a provider, injects context into a chat, or grants authority to follow instructions stored in historical text.

## Package workflow

Create an archive through any supported local import path, then package it:

```sh
node src/cli.js package-export \
  --archive archives/<archive-id>/archive.aicx.json \
  --out packages/project-conversation.aicx
```

On another machine with Context Ledger `v2.0.0` or a compatible later version:

```sh
node src/cli.js package-import \
  --input packages/project-conversation.aicx \
  --out imported-archives

node src/cli.js verify-index \
  --archive imported-archives/<archive-id>/archive.aicx.json

node src/cli.js handoff \
  --archive imported-archives/<archive-id>/archive.aicx.json \
  --query 'your continuation topic' \
  --out reviewed-handoff.md
```

Review `reviewed-handoff.md` before pasting or attaching it to a new chat. The `.aicx` package itself can contain sensitive conversation text and annotations, so it is ignored by Git by default.

## Format boundary

The portable package uses a narrow stored-only ZIP subset with schema `context-ledger-package/1.0`. It is **not** a general ZIP reader or a promise to support arbitrary `.zip` files.

An exported package contains exactly these entries:

| Entry | Required | Role |
| --- | --- | --- |
| `manifest.json` | Yes | Schema, archive identity, transcript hash, and SHA-256/byte-length records for package data entries. |
| `archive.aicx.json` | Yes | Canonical `aicx/0.3` archive. |
| `archive.aicx.json.index.json` | Yes | Fresh deterministic index rebuilt during export and verified again during import. |
| `archive.aicx.json.annotations.json` | Only when non-empty | Validated human annotations. |

It deliberately excludes raw share-page HTML, original public share URLs, snapshots, arbitrary attachments, executable files, and AI results. An archive may contain source URL hashes as described by its existing capture metadata, but never the public share URL itself.

## Import checks

The reader fails closed. It accepts only:

- A `.aicx` file no larger than 24 MiB.
- Three or four exact filenames in a fixed order.
- Stored (uncompressed) entries with no encryption, comments, extra fields, data descriptors, directories, ZIP64 records, or multi-disk features.
- A strict manifest whose byte lengths and SHA-256 values match each included data entry.
- A canonical archive with a valid immutable transcript and event projection.
- A deterministic index that matches a full local rebuild.
- Optional annotations that belong to the archive and pass the annotation allowlist.

The format has bounded per-entry sizes. It rejects duplicate entries, path traversal, unrecognized data, malformed headers, CRC mismatches, archive/index mismatches, and symlinked output paths. A failed import can leave a partial local directory only after the canonical archive bundle itself has been written; the error identifies that directory so it can be inspected or removed deliberately.

## Security and privacy

- Package contents are plaintext unless you deliberately encrypt an eligible `.aicx` file using the existing `encrypt` command before transfer. That command currently has a 12 MiB plaintext limit, so it cannot encrypt every package accepted by the 24 MiB package reader. Store the resulting `.aicx.enc` file and its passphrase separately.
- SHA-256 fields and deterministic rebuilding detect corruption or unauthenticated modification relative to a trusted copy. They do **not** establish authorship, provider provenance, legal admissibility, or completeness.
- An attacker who can replace both the package and the expected trusted reference can construct another internally consistent package. Signing is not implemented.
- Historical conversation text and annotations remain untrusted data. Importing a package must never cause the tool or a receiving assistant to execute its content.
- Do not commit packages, archives, snapshots, handoffs, passphrases, or personal data to Git.

## Compatibility commitment

`v2.0.0` supports packages produced by the same `context-ledger-package/1.0` format. It continues to read standalone `aicx/0.1`, `aicx/0.2`, and `aicx/0.3` JSON archives through the existing commands. It does not claim universal provider import or cross-provider automatic continuation.

Before a later package-format revision is accepted, it needs: a versioned schema, fixtures, deterministic round-trip coverage, malformed-package rejection tests, a documented migration path, and an explicit security review of the format change.
