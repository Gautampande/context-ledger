# Guided handoff and usability evaluation (included in v2.0.0)

## Goal

Make the normal archive-to-new-chat workflow clear for a person who has not used Context Ledger before. The tool must not imply that ChatGPT, Claude, Gemini, or another AI product automatically imports archives; the person still reviews and pastes or attaches a generated handoff through the target product's normal interface.

## One-command handoff

```sh
node src/cli.js handoff \
  --archive archives/<archive-id>/archive.aicx.json \
  --query 'authentication decision' \
  --out reviewed-handoff.md
```

The command validates the source archive, uses the verified local index when available, includes bounded selected evidence and manual annotations, and writes one new Markdown file. It makes zero AI calls and zero network requests.

Review `reviewed-handoff.md` before sharing it. The file includes:

- Plain-language instructions for the person moving the work.
- A target-neutral safety instruction for the receiving assistant.
- The existing evidence-bounded continuation packet with archive hash and event IDs.

Use either `--query` or one or more `--select <event-id>` values. With neither, the handoff uses relevant pins or the recent bounded conversation context.

## Recommended independent usability evaluation

When independent first-time users become available, ask three people who have not previously used Context Ledger to complete this task on their own:

1. Start from a prepared non-sensitive sample archive and a written two-line goal: “create a reviewed handoff for a new chat.”
2. Find the documented command, generate a handoff, open and review it, and identify what they would paste or attach to a new chat.
3. Finish within five minutes without live maintainer guidance.

Record only aggregate, non-sensitive results: number of participants, completion count, time range, steps where people became stuck, and resulting documentation or interface changes. Do not collect participant names, private chats, generated handoffs, URLs, or screen recordings in Git.

## Evidence status

This evaluation has not been run for the `v2.0.0` development line and must not be represented as completed. It remains the preferred protocol for collecting future usability evidence:

1. Confirm guided-handoff tests, syntax check, and release check pass.
2. Have three new users independently complete the task within five minutes.
3. Fix observed confusion or document it as a known limitation.
4. Publish only aggregate findings and remaining limitations.

The feature was initially planned for a standalone `v1.4.0`, then bundled into an untagged `v1.5.0` evidence plan. It is now included in `v2.0.0`; no standalone `v1.4.0` or `v1.5.0` tag is planned.
